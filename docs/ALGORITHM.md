# Algorithm notes / 算法说明

> 这份文档解释「引擎到底在算什么」，以及为什么这样算。
> 想先看结果，直接跳到 [Refactor notes](REFACTOR_NOTES.md) 的对照表。

## 1. 问题设定 / Problem setup

双色球每期从 1–33 中开出 6 个不重复红球（蓝球本文不涉及）。
目标不是「预测中奖」——那在数学上不成立——而是：

> **给定一段历史，能否构造一个排序，使靠前的号码命中率长期高于盲选？**

盲选的期望命中数是解析可算的：

$$
\mathbb{E}[\text{hits}] = k \cdot \frac{6}{33}
$$

取 `k = 6` 时约为 **1.09**。这就是本文所有实验的及格线。任何策略的长期均值如果贴着 1.09，
说明它没有提供任何信息量。

## 2. 评分原语：邻域扩散权重 / Neighbourhood diffusion

一期开奖 $\mathcal{D} = \{d_1,\dots,d_6\}$ 被投影成 33 维向量 $w \in \mathbb{R}^{33}$：

$$
w_{d} \mathrel{+}= h,\qquad w_{d-1} \mathrel{+}= \delta,\qquad w_{d+1} \mathrel{+}= \delta
$$

其中 $h$ 是 `hit`（命中权重），$\delta$ 是 `diffusive`（扩散权重），下标越界不做环形回绕。
累计过去 $L$ 期的向量得到当期得分：

$$
s_t = \sum_{i=t-L}^{t-1} w_i
$$

按 $s_t$ 降序排列 1–33，得到当期排序 $\pi_t$。同分时号码小者在前（保证可复现）。

**这一步的假设**：开奖号码之间存在邻域惯性，命中给强信号、邻居给弱信号。
这个假设是否成立，不靠直觉，靠第 3 节的回测。

## 3. 三种策略 / Three strategies

| 策略 | 排序依据 | 本质 |
| --- | --- | --- |
| `topk` | $s_t$ 前 k 名 | 直接信任得分 |
| `rank-factor` | 统计「第几位最容易命中」，按位次取号 | 信任**位次**而非得分 |
| `ensemble` | 多个 $L$ 各投一票，按票数取号 | 信任**共识** |

`rank-factor` 的动机来自手稿 `test_1`：得分绝对值可能不重要，但「排在第一名/第三名的号码
历史上是否更容易真开出」这件事也许有规律。于是把每期的命中记在位次上，累计成 33 个计数，
取计数最高的 k 个位次，以后就固定取这几个位次上的号码。

`ensemble` 把手稿 `test_5` 的多窗口思路形式化：$L \in \{1,\dots,19\}$ 各算一个「专家」，
每个专家按自己学到的位次推荐 k 个号，加总票数后取最高的 k 个。

## 4. 最重要的方法学修正：前视偏差 / Look-ahead bias

手稿 `test_3.py` / `test_4.py` / `test_5.py` 在挖掘「优秀位次」时遍历了**全部历史**，
包括它即将预测的那些期。这在回测里叫 look-ahead bias，会让结果系统性虚高。

本项目把这个开关显式化：

```python
BacktestConfig(mode="expanding")  # 默认：第 t 期只使用 t 之前的信息
BacktestConfig(mode="full")       # 复刻手稿口径：用全样本挖因子（含未来）
```

同一批真实数据（283 期）、同一套代码、只切这个开关，`ensemble` 的每期平均命中数从 **1.12 → 1.58**
（见 `examples/output/03_leakage_bias.png`）。这就是「看起来有效」的来源。

**结论**：在这个问题上，去掉前视之后所有策略都回到基线附近。
本项目因此把「可复现的回测框架 + 偏差检测」作为主要价值，而不是选号结果本身。

## 5. 统计口径 / Metrics

- `average_hits`：每期命中数的均值，主要指标。
- `average_hit_rate`：命中数 / 6，手稿口径。
- `baseline_hits`：解析基线 $k \cdot 6/33$。
- `lift`：`average_hits / baseline_hits`，> 1 表示跑赢盲选。
- `distribution`：命中数 0–6 的频次表，配合超几何分布基线看整体形状。
- `z_score`：`(均值 − 基线) / sqrt(Var/n)`，其中 `Var = k·p·(1−p)·(33−k)/32`、`p = 6/33`。
  因为预测集合在开奖前固定，每轮命中数严格服从 `Hypergeometric(33, 6, k)`，
  所以这个 z 是解析量而非抽样估计——它是「是否只是运气」的唯一硬指标。

仅看均值容易被少数几轮极值带偏，因此所有结果同时提供**滚动曲线**（`plot_rolling_hits`）。

## 6. 复杂度 / Complexity

设期数 $N$、窗口数 $H$、池大小 $P=33$：

| 步骤 | 复杂度 | 备注 |
| --- | --- | --- |
| 权重矩阵 | $O(NP)$ | 一次构建，全局复用 |
| 单窗口得分 | $O(LP)$ | `window_scores` |
| 增量位次统计 | $O(NHP\log P)$ | 手稿的每轮重算是 $O(N^2HP\log P)$ |

手稿在 300 期、19 个窗口下需要分钟级；重构后同一任务 < 1 秒，且结果逐位一致
（`tests/test_backtest.py::test_incremental_tracker_matches_batch` 锁死了这一点）。

## 7. 边界与已知限制 / Limits

- 蓝球未建模（手稿只解析不使用）。
- 没有考虑开奖区间、和值、奇偶比等结构性特征，这些属于 v2 的候选方向。
- 283 期样本下，单轮命中数服从超几何分布；`z` 分数（`metrics.z_score`）用于把「增益」翻译成标准误，`|z| < 2` 视为噪声。
- 合成数据由 `make_synthetic_draws` 生成，用于离线验证；真实样本在 `data/sample/`。
- 本项目不提供任何形式的购彩建议。
